Author: **oracleyu**. Top module: `tt_um_oracleyu_pwm_v2`. Open-source educational Tiny Tapeout SKY130 user macro, based on the official SKY Verilog template. Apache-2.0; upstream notices are retained.

Two registered 8-bit PWM channels share a programmable divider. SPI Mode 0 receives a complete five-byte configuration, stages it in a one-entry buffer and applies both duties, divider and enable atomically at the old PWM period boundary. Status reads include a generation toggle and sticky format/queue errors. Reset asserts asynchronously and releases synchronously. SPI is oversampled in the system-clock domain.

## Interface

| Signal | Meaning |
|---|---|
| ui_in[0], [1], [2] | SPI SCK, CS_n, MOSI |
| uo_out[0], [1], [2] | PWM left, PWM right, dedicated push-pull MISO |
| uo_out[3], [4], [5], [6], [7] | pending, active enable, phase MSB, error, period pulse |
| clk / rst_n / ena | system clock / reset / Tiny Tapeout selection |

`duty=code/256`; `f_pwm=f_clk/(256*N)`, N=1..256. Recommended bench setup: independent 10 MHz system clock, 100 kHz SPI, N=2, duties 64/192 gives approximately 19.53125 kHz at 25%/75%. MISO is not tristated. SPI high/low and CS setup/hold/idle intervals must each be at least eight system-clock cycles.

## Verification and build

The same external-pin Cocotb test checks all 256 duty codes, divider boundaries, atomic updates, queue rejection, malformed frames, pause/resume, reset during a frame and registered-output stability. The local pre-publication baseline passed 1,269,432 system clocks and 1,387 SPI frames for each of RTL, generic, standalone SKY130, final unpowered and final powered models. The published top was namespaced for this repository; its CI rebuild and artifacts are the authority for this revision, not the previous baseline GDS.

GitHub Actions uses the official Tiny Tapeout SKY26d GDS, precheck, GL test and docs actions, with LibreLane 3.0.14. The GDS and docs artifacts are generated by CI. A passing workflow is a local/CI verification result, not fabrication-service acceptance.

For an M1 Mac with Homebrew, Python 3.13 and running Docker Desktop:

```bash
git clone --recurse-submodules https://github.com/oracleyu/tt-pwm-controller-v2.git
cd tt-pwm-controller-v2
make setup
make all
make precheck-setup
make precheck
make package
```

The `tt` submodule is pinned to 9d13ff3e3e6202090740110438c6a10c1d62ca0f. Tool image and PDK hashes are in [source-lock.json](source-lock.json). First setup downloads several GB; reserve at least 15 GB. Subsequent runs reuse downloads. `make all` archives previous physical runs and rebuilds. If RTL or constraints change, run `make fresh` before an individual `make gds`; do not resume stale physical state with changed sources.

`constraints/pwm.sdc` targets 50 MHz and 50 fF loads. Only the three asynchronous SPI ingress ports and raw reset have explicit timing exceptions; internal synchronizer and reset-release paths remain timed. `make sta-check cdc-audit` reads back final parasitics and maps intentional asynchronous first-stage endpoints. This is not an MTBF certification. Functional gate tests do not apply SDF; extracted multi-corner timing is checked separately.

Local evidence is written to `reports/`, `src/runs/tutorial/` and `tt/precheck/reports/` and is excluded from source commits. `make package` bundles local evidence without tools, caches or PDK binaries. `make firmware-test` runs strict C11/ASan/UBSan host tests using simulated SPI callbacks.

## Submission and hardware status

No physical MCU/FPGA/ASIC board test has been performed. The Arduino adapter has not been built with a board-specific SDK. Use the wiring document and record actual hardware results separately. No manufacturing order or payment has been made. This is a user macro, not a standalone padframe/package design; final shuttle compatibility, integration, service acceptance and silicon testing remain separate steps.
